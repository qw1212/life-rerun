# 人生模拟器：美好人生叙事之旅 — 开发计划

## 第一阶段：项目架构与初始化

1. 确定技术栈（推荐 MVP 方案起步）：
   - 前端：React 18 + TypeScript + Vite
   - 样式：Tailwind CSS + shadcn/ui
   - 状态：Zustand + localStorage 持久化
   - 后端：Node.js + Express
   - AI：OpenAI / Claude / 国产大模型 API
   - 数据库：SQLite
2. 初始化 Monorepo 或简单目录结构：
   - `apps/web/` — 前端
   - `apps/server/` — 后端
   - `docs/` — 设计文档
3. 配置前端开发环境：
   - Vite + React + TypeScript
   - Tailwind CSS
   - ESLint + Prettier
4. 配置后端开发环境：
   - Express + TypeScript
   - 环境变量管理（`.env.example`）
   - CORS 与基础路由
5. 编写 `README.md` 与 `docs/design.md` 初稿。

**第一阶段状态：已完成** ✅（技术栈按 MVP 调整：数据库先用 JSON 文件替代 SQLite，避免本机编译依赖；前后端 typecheck 通过。）

## 第二阶段：核心数据与游戏模型设计

6. 在共享包或前端 `types/` 中定义核心类型：
   - 玩家属性：智力、体质、魅力、家境、运气、心理韧性
   - 年龄阶段与人生主题
   - 事件模板、选项结构、结局结构
7. 设计天赋系统：
   - 普通天赋（属性加成）
   - 特殊天赋（解锁隐藏剧情）
   - 心理天赋（影响韧性恢复、积极事件概率）
8. 设计事件触发规则：
   - 按年龄阶段触发
   - 按属性阈值触发
   - 按前置事件/人生主线触发
   - 按随机概率与运气加权触发
9. 建立事件库（至少 50 个）：
   - 普通事件 30 个
   - 爽文/高光事件 10 个
   - 低谷事件 5 个（必须带成长后续）
   - 顿悟事件 5 个
10. 设计人生主线分支：
    - 学术线、创业线、艺术线、社会服务线、平凡幸福线等。

**第二阶段状态：已完成** ✅（核心类型放在 `packages/shared`；天赋 15 个；事件库 57 个，含普通/高光/低谷/顿悟/喘息/里程碑；触发规则与主线分支检测已落地；全工程 typecheck 通过。）

## 第三阶段：AI 叙事引擎搭建

11. 在后端创建 `/api/narrative` 接口：
    - 接收玩家状态（属性、年龄、历史、情绪标签）
    - 调用大模型 API 生成故事与选项
    - 返回结构化 JSON
12. 编写核心 Prompt 模板：
    - System Prompt：定义温暖、积极、成长型的叙事者人格
    - User Prompt：结构化输入玩家状态
    - 输出格式约束：`story`、`options`、`psychologyHint`、`attributeChanges`
13. 实现内容安全过滤：
    - 禁用自伤、暴力、歧视等敏感主题
    - 低谷事件后强制跟随后续支持事件
14. 实现 AI 响应缓存：
    - 使用 Redis 或内存缓存相似状态的结果
    - 本地 localStorage 二次缓存
15. 实现降级策略：
    - AI 不可用时回退到模板事件库
    - 轻量模型处理常见事件，强模型处理关键节点

**第三阶段状态：已完成** ✅（`/api/narrative` 已接入 AI provider + Prompt 模板；输入/输出安全过滤；内存缓存；无 API key 或 AI 失败时自动降级到 57 个模板事件库；全工程 typecheck 通过。）

## 第四阶段：玩家状态与存档系统

16. 实现 `Player` 状态管理（Zustand）：
    - 属性存储与初始化
    - 年龄推进与阶段判断
    - 天赋与已发生事件记录
    - 心理韧性值与情绪标签
17. 实现存档/读档：
    - localStorage 自动保存
    - 手动存档槽位
    - 导出/导入"人生之书"
18. 实现数值平衡：
    - 属性上限与下限
    - 事件影响的合理区间
    - 心理韧性的恢复公式

**第四阶段状态：已完成** ✅（Zustand 玩家状态管理 + localStorage 自动保存 + 手动存档槽位 + 导出人生之书；属性/PERMA/韧性 clamp、韧性恢复公式、事件影响应用已落地；基础可玩 UI 已可用。）

## 第五阶段：前端 UI 与交互

19. 设计视觉系统：
    - 主题色：温暖、治愈、希望感
    - 卡片式事件展示
    - 属性面板与人生时间轴
    - 动效：Framer Motion 实现事件切换、属性变化动画
20. 实现页面/组件：
    - 欢迎页 + 心理安全提示
    - 角色创建页（天赋抽取、属性分配、心情打卡）
    - 心理热身页（呼吸动画 / 积极 affirmations）
    - 主游戏页（事件展示、选项列表、属性面板、人生日志）
    - 顿悟页（低谷后的反思选择）
    - 结局页（人生成就 + 心理成长报告 + 人生之书）
21. 实现交互细节：
    - 选项悬停提示
    - 选择后的即时反馈与心理提示
    - 进入下一年按钮
    - 暂停/退出/重新开始
22. 响应式适配：
    - 移动端优先的卡片布局
    - 字体与按钮大小适配

**第五阶段状态：已完成** ✅（主题色/卡片/时间轴/动效已落地；欢迎页、角色创建页、主游戏页、结局页已接入 App；天赋属性加成与心情初始化已生效；ESLint 配置补齐，`typecheck`/`lint`/`build` 均通过。其中「心理热身页」与「顿悟页」与第六阶段的 PERMA、韧性、叙事疗法逻辑耦合更紧，调整至第六阶段统一实现。）

## 第六阶段：积极心理学与叙事疗法功能

23. 集成 PERMA 模型：
    - 每个事件标注影响的 PERMA 维度
    - 结局报告展示五维雷达图
24. 实现心理韧性系统：
    - 低谷事件降低情境值
    - 成长型选择恢复韧性
    - 韧性影响顿悟事件触发概率
25. 实现叙事疗法元素：
    - 外化问题：挫折事件使用"这是挑战，不是定义"的文案
    - 重写故事：结局时让玩家选择最想保留的品质
    - 独特结果：在日志中高亮玩家的勇敢选择
26. 实现感恩/反思日志：
    - 每轮结束后可选写下 1~3 件感恩的事
    - AI 可在后续故事中引用玩家写下的内容
27. 实现"心理急救"机制：
    - 连续负面事件后触发"喘息事件"
    - 提供暂停按钮与呼吸引导
    - 结局强调多元价值，避免单一成功标准

**第六阶段状态：已完成** ✅（结局页已集成 PERMA 雷达图；韧性系统已落地；顿悟页使用叙事疗法外化问题文案；人生时间轴高亮「勇敢选择」；AI Prompt 已加入感恩日志与 PERMA 维度；连续低谷强制喘息/顿悟事件；主游戏页新增呼吸暂停按钮；`typecheck`/`lint`/`build` 均通过。）

## 第七阶段：可玩性增强

28. 实现选项类型系统：
    - 稳妥型、冒险型、关系型、成长型、接纳型、意义型
    - 隐藏选项解锁条件
29. 实现人生主线分支：
    - 根据连续选择进入不同主线
    - 主线影响事件池与结局
30. 实现贵人系统：
    - 在关键节点随机或按条件触发贵人相助
    - 贵人类型：导师、挚友、伴侣、陌生人
31. 实现打脸/高光事件：
    - 曾经否定你的人最终认可你
    - 强调内在成长，避免纯粹报复快感
32. 实现随机性与掌控感平衡：
    - 属性影响概率
    - 关键节点选择权重
    - 人生预览模糊提示

## 第八阶段：测试、打磨与伦理审查

33. 多轮试玩测试：
    - 检查事件链是否通顺
    - 验证 AI 生成内容的稳定性与安全性
    - 调整数值平衡，确保爽文感与成长感并存
34. 内容伦理审查：
    - 所有低谷事件必须有成长出口
    - 移除可能引发不适的内容
    - 强化免责声明与求助信息
35. 性能优化：
    - 减少 AI 请求延迟
    - 优化前端渲染性能
    - 压缩静态资源
36. 移动端与可访问性测试：
    - 屏幕阅读器兼容
    - 键盘操作支持
    - 不同尺寸设备适配

**第八阶段状态：已完成** ✅（全阶段事件已审查，所有低谷事件均配置成长/希望出口；AI 提示词加入安全约束、贵人信息、JSON 输出规范与心理危机求助信息；输入/输出安全检查升级，低情绪触发求助热线；前后端 fetch 增加 20s/25s 超时；WelcomePage 与 AttributePanel 增加 aria 可访问性标注；App.tsx 选项回调使用 useCallback 减少重渲染；`typecheck`/`lint`/`build` 均通过。）

## 第九阶段：打包与部署

37. 确定上线形态：
    - 核心形态：响应式 Web PWA（手机/平板/电脑通用）
    - 架构：前后端分离（B 方案），前端 CDN + 后端容器，长期可扩展性最好
    - 未来可选：Capacitor/Tauri 包壳成原生 App/桌面端，业务代码基本复用
38. 前端 PWA 化：
    - `vite-plugin-pwa` 生成 manifest、Service Worker、离线缓存
    - 图标、主题色、可安装配置
39. 编写生产构建与部署配置：
    - 前端 `npm run build` + `VITE_API_BASE_URL`
    - 后端 Dockerfile + 健康检查
    - `docker-compose.yml` + Nginx 全栈一键部署（本地/单机方案）
40. 部署到测试环境并验证完整流程。
41. 更新 README 与文档，整理 API 说明。
42. 收集首批用户反馈，迭代 Prompt 与事件库。

**第九阶段状态：部署架构已完成** ✅（PWA 配置、前后端 Dockerfile、docker-compose、环境变量示例、生产静态服务已落地；`typecheck`/`lint`/`build` 通过；Docker 环境待实际机器验证。）
